Workspace Agents in ChatGPT Work

A practical guide for turning repeatable Persimmon workflows into reliable, shareable help

Most of us use ChatGPT by opening a chat, asking for something, and reviewing the response. A workspace agent goes a step further: it is configured to take responsibility for a repeatable job, use the right tools and instructions, and produce a consistent result. Everything described here can be done in the ChatGPT web interface; no desktop app is required.

The Idea

What is a workspace agent?

A workspace agent is a shared AI worker designed for a defined workflow. You give it a role, clear instructions, approved apps, and the standards it should follow. It can then complete a multi-step task on demand or on a schedule, and it can be shared with teammates in your ChatGPT workspace.

A workspace agent can combine:

  • Instructions that define its objective, steps, boundaries, and expected output.
  • Connected apps that let it read or act in approved systems such as calendars, email, shared drives, and project tools.
  • Skills that package a repeatable method, template, examples, or quality standard.
  • Memory that preserves useful context between runs for each individual user.
  • Schedules and sharing so the workflow can run routinely and support more than one person.
The distinction

The important distinction is responsibility. A chat helps with the task in front of you. A workspace agent is set up to carry a particular workflow from input to finished output. It still needs human oversight, especially when information is sensitive or an action is difficult to reverse.

Where It Fits

Where could we use agents at Persimmon?

The best opportunities are recurring workflows with recognizable inputs, a stable sequence of steps, and a useful deliverable. The goal is not to automate an entire function. It is to remove the repetitive coordination work around a focused outcome.

Project management

  • Meeting-to-action workflow: turn notes into log entries (issues, decisions, actions, etc.), then update your personal to-do list based on the changes.
  • Project health check: compare the current plan, recent status reports, and open actions to flag stale work, missing owners, or schedule pressure.

Sales

  • Meeting prep: Look at incoming leads, gather recent account context, add relevant public news, and create a concise briefing.
  • Pre-proposals: Look at call notes and draft a pre-proposal based on a defined template and rules.

Instructional design

  • Content research: take a presentation outline or deck and research supporting statistics or studies, producing a list aligned to slide numbers.
  • Quality review: check a course or job aid for objective alignment, accessibility, consistency, tone, and missing review evidence, then produce an actionable revision list.
Where It Fits

Agents and Skills: how do they fit together?

These tools overlap, but they solve different parts of the problem. They work best as layers rather than competitors.

  • Workspace agent: use it when one AI worker should own a repeatable, multi-step workflow, use connected apps, and possibly run on a schedule or be shared with a team. A single agent can call multiple skills.
  • Skill: use it when the method needs to be consistent. A skill is a reusable playbook containing instructions, templates, examples, reference material, or scripts. A skill can be used directly in ChatGPT or attached to an agent.
Building One

How to configure a workspace agent on the web

Open ChatGPT in your browser, select Agents from the navigation, and choose the option to build a new agent. If you do not see Agents or cannot create one, contact your workspace administrator.

  1. Describe the job in plain language. State the trigger, inputs, steps, output, destination, exclusions, and when the agent must stop and ask for help.
  2. Review the profile and instructions. Give the agent a specific name and description. Edit the generated instructions until the scope, sequence, quality bar, and boundaries are explicit.
  3. Connect only the apps it needs. Choose the minimum sources and actions required for the workflow. Confirm that each app has been approved for the workspace.
  4. Add skills, templates, and examples. Attach a focused skill when the agent should follow a repeatable Persimmon process or output format. Include one or two strong examples whenever possible.
  5. Decide whether memory is useful. Enable memory only when context from prior runs will improve future work. Remember that agent memory is per user, not shared across everyone using the agent.
  6. Test in Preview or Try in ChatGPT. Use realistic inputs, missing-data cases, permission failures, and examples that should be excluded. Compare the result with a strong human-created output.
  7. Deploy deliberately. After testing, choose the appropriate channel, schedule, and sharing settings. A new agent is private to its creator until sharing is enabled.
Building One

Best practices for reliable agents

  • Start narrow. One outcome, one audience, and one clear definition of done are easier to test and improve than a broad 'do everything' agent. An agent that produces class handouts (narrow) is stronger than one that builds outlines, creates decks, QCs classes, and critiques finished product (overly broad).
  • Map the workflow first. Document the human process, decision points, exceptions, and required sources before asking the builder to automate it.
  • Write for action. Specify what the agent should do, what it should not do, what evidence it must use, and the exact form of the finished deliverable.
  • Build in human checkpoints. Require review before sending messages, updating records, publishing content, or making commitments on behalf of Persimmon.
  • Test the uncomfortable cases. Try incomplete inputs, conflicting sources, unusual dates, restricted files, duplicate records, and requests outside scope.
  • Improve from evidence. Save examples of good and poor results, refine the instructions or skill, and retest before expanding access or adding a schedule.
Building One

Is this a good first agent?

A workflow is a strong candidate when most of these statements are true:

  • It happens often enough that the saved time will matter.
  • The required inputs can be identified and accessed through approved sources.
  • The major steps and exceptions can be explained clearly.
  • The finished output has a recognizable format and quality standard.
  • Errors can be spotted in review and corrected without serious harm.
  • A person or team can own testing, maintenance, and access decisions.
When to keep it human-led

If the work is highly ambiguous, rarely repeated, politically sensitive, or difficult to reverse, keep it in a human-led chat or use a skill to support the person doing the work. An agent should earn broader access through reliable results.

In Short

The simplest way to think about it

A skill knows the method. A workspace agent owns the workflow.

Start with a small, useful job; give the agent the minimum access it needs; test it against real examples; and keep a human accountable for the result.
